Case study — shipped & owned end to end

DualProfile

Chrome extension SaaS · vivaup.org · Manifest V3 + Convex

Live — paying users

WhatsApp Web renders one profile photo to everyone in your contact list. DualProfile lets a user assign a different photo per contact — visible only to that person — with mutual detection running on hashed phone-number lookup between two installs.

  • ProblemI don't control WhatsApp Web's DOM, and it changes under me without warning.
  • DecisionMutationObserver over polling to catch header re-renders live, with a polling fallback for anything the observer misses — overlay rendering degrades gracefully instead of breaking outright.
  • IncidentSelector drift under real users when WhatsApp shifted its DOM structure. Treated each break as a signal to harden the targeting logic, not just patch the symptom.
  • Trade-offConvex over custom backend infra — accepted vendor lock-in to ship real-time sync solo, instead of over-engineering for scale I didn't have yet.
  • MonetisationPer-feature tier entitlements (Free/Pro/Annual/Lifetime) driven by webhook metadata, not one binary paid flag — features gate and price independently as the product grows.

Case study — applied AI systems architecture

KasaFlow

AI backend · Python / FastAPI · OpenAI Responses API

In production

A backend service that takes a customer's natural-language message and returns structured, machine-readable business data — intent, product, material, language, confidence — for downstream workflows to act on without parsing raw text.

  • V1Rule-based intent recognition engine. Predictable, but brittle against real customer phrasing.
  • MigrationSwapped the extraction engine for GPT-4.1-mini via the OpenAI Responses API — without changing the public API contract consumers already depended on.
  • ArchitectureDedicated LLM service layer sits behind the API — the contract stays stable no matter what's doing the extraction underneath.
  • OutputStructured JSON schema (intent · product · material · language · confidence) instead of raw model text, so downstream systems get something they can trust.
  • ReliabilityDeterministic bypass layer resolves narrow follow-up answers — delivery zone, material, quantity, confirmation, karat options — without a second LLM round-trip, and enforces price/variant invariants no prompt is trusted to hold on its own.
  • CoverageGoogle Geocoding integration resolves delivery zones across all 16 regions of Ghana, falling back to a curated Accra/Kumasi neighbourhood list when no key is configured — plus order-status lookup and cancellation. Extended after a 50-turn live audit surfaced real gaps: exact-catalogue lookups no longer silently degrade to fuzzy search, and known local landmarks resolve to the right delivery zone.
  • HumanizationStarted work on a bounded acknowledgment layer and pushback/tone classification, so corrections read as "sorry, updated that" rather than a robotic re-ask — with custom orders and anything needing judgement handed to a human, not the model.
